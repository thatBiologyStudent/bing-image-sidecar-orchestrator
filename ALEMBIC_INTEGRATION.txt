Alembic <-> Bing Image Sidecar Orchestrator integration: instructions for the Alembic agent
====================================================================================

Audience: an AI coding agent (or developer) working in the Alembic Generative Studio
repository (E:\NXTCloud\Tools\Alembic-Generative-Studio, GitHub thatBiologyStudent/alembic-generative-studio).

Goal: add Bing Image Creator as an image provider in Alembic. Alembic's chat agent then
generates and edits images in Bing Image Creator through the Bing Image Sidecar Orchestrator
browser extension, the same way it already uses Flow Sidecar, ComfyUI, A1111 or OpenAI.

Everything on the extension side is already done (Bing Image Sidecar Orchestrator 1.0.0).
All work below happens in the Alembic repository.


1. HOW IT WORKS
---------------

Alembic tab (localhost:5178 / thatbio.vercel.app)  --window.postMessage-->  bridge/alembic-bridge.js
                                                                                  |
                                                                           background.js
                                                                                  |
                                                                           content.js (drives Bing UI)

- The extension injects bridge/alembic-bridge.js into Alembic pages on:
    http://localhost:5178/*
    http://127.0.0.1:5178/*
    https://thatbio.vercel.app/*
  Alembic talks to it with window.postMessage. No extension ID, npm package, or server change is needed.
- The user must tick "Allow Alembic to control Bing" in the Bing Image Sidecar Orchestrator side panel
  (off by default) and keep a Bing Image Creator tab open (https://www.bing.com/images/create/ai-image-generator).
- Each generate call sets Bing's aspect ratio (1:1, 3:2, or 2:3), optionally attaches a reference image
  (image-to-image / edit), types the prompt, clicks Generate, waits for completion, and returns up to
  4 images as base64 data URLs.
- One generation runs at a time. Note: if the user is signed out of Microsoft/Bing, Bing adds a watermark
  to generated images.


2. BRIDGE PROTOCOL (VERSION 1)
------------------------------

All messages are posted with window.postMessage(message, window.location.origin) and must be read only
when event.source === window && event.origin === window.location.origin.

Request (Alembic -> extension):
  { __bingSidecar: "request", id: string /* crypto.randomUUID() */, action: string, params?: object }

Responses (extension -> Alembic):
  { __bingSidecar: "response", id, ok: true,  result: any }
  { __bingSidecar: "response", id, ok: false, error: string, code: string }

Optional progress event (generate only, stage "submitting"):
  { __bingSidecar: "event", id, event: "progress", stage: string, detail?: any }

Ready event (posted once when bridge loads; use "hello" for detection):
  { __bingSidecar: "ready", protocol: 1, version: "1.0.0" }

If the extension is not installed (or the page isn't on an allowed origin), nothing answers.
Treat a "hello" without reply within 3 s as "not installed".

Actions:
  - hello / status
    params: {}
    result: {
      protocol: 1,
      version: "1.0.0",
      enabled: boolean,
      busy: boolean,
      bing: { open: boolean, signedOut: boolean, url: string, title: string },
      capabilities: {
        models: ["MAI-Image-2.6-Flash"],
        defaultModel: "MAI-Image-2.6-Flash",
        aspectRatios: ["1:1", "3:2", "2:3"],
        maxImagesPerRequest: 4,
        maxReferences: 1,
        img2img: true,
        inpaint: false,
        negativePrompt: false,
        seed: false,
        outputResolution: "1K"
      }
    }

  - generate
    params: {
      prompt: string,
      aspectRatio?: "1:1" | "3:2" | "2:3",
      count?: number (1..4),
      references?: Array<{ dataUrl?: string, name?: string }>,
      download?: boolean (default false)
    }
    result: {
      images: Array<{ dataUrl: string }>,
      model: "MAI-Image-2.6-Flash",
      aspectRatio: string,
      downloaded: boolean
    }

Error codes:
  DISABLED            -> Bridge is off: tick "Allow Alembic to control Bing" in the side panel.
  NO_BING_TAB         -> Open https://www.bing.com/images/create/ai-image-generator in a tab.
  BUSY                -> Another generation is running: wait ~5 s and retry.
  BING_ERROR          -> Bing UI automation failed or content policy blocked the prompt.
  BAD_REQUEST         -> Invalid params (e.g. missing prompt or unsupported aspectRatio).
  EXTENSION_RELOADED / DISCONNECTED -> Extension was reloaded: refresh the Alembic page.
  TIMEOUT / NOT_INSTALLED -> Client-side timeout / extension not active on this origin.


3. IMPLEMENTATION IN ALEMBIC
----------------------------

3.1 New file: src/providers/image/bingSidecarClient.ts

Mirror flowSidecarClient.ts using __bingSidecar instead of __flowSidecar:
- BING_SIDECAR_PROTOCOL = 1
- BING_ASPECTS = ['1:1', '3:2', '2:3'] as const
- BING_DEFAULT_MODELS = ['MAI-Image-2.6-Flash']
- bingSidecarRequest<T>(action, params, opts): posts { __bingSidecar: 'request', id, action, params }
  and resolves/rejects on matching { __bingSidecar: 'response', id, ... }.
- bingSidecarHello(): calls bingSidecarRequest('hello', {}, { timeoutMs: 3000 }).
- ensureBingReady(): verifies protocol === 1, enabled === true, and bing.open === true.

3.2 New file: src/providers/image/bingSidecar.ts

Mirror FlowSidecarBackend as BingSidecarBackend implements ImageBackend:
- capabilities:
    img2img: true, inpaint: false, upscale: false, interrogate: false,
    negative: false, steps: false, samplers: false, seed: false, denoise: false,
    promptStyle: 'natural'
- listModels(): returns (await bingSidecarHello()).capabilities.models, fallback BING_DEFAULT_MODELS.
- txt2img(p, ctx): calls run(p, [], ctx).
- img2img(p, ctx): rejects if p.mask is set; converts p.image via blobToDataUrl and passes
  references: [{ dataUrl, name: 'Alembic source image' }] to run().
- run(): maps width/height with nearestAspect(p.width, p.height, [...BING_ASPECTS]),
  loops up to p.count (max 4 per request), retries on BUSY every 5 s (up to 12 attempts),
  and converts each returned dataUrl with base64ToBlob(img.dataUrl).

3.3 Wire into Alembic's provider system

1. src/db/schema.ts:
   Add 'bing-sidecar' to the ImageApi union type.
2. src/providers/image/index.ts:
   Import BingSidecarBackend and add `case 'bing-sidecar': return new BingSidecarBackend(conn);`
3. src/providers/presets.ts:
   Add preset id 'bing-sidecar', name 'Bing Image Creator (Bing Sidecar extension)',
   group 'Other', baseUrl '', imageApi 'bing-sidecar', keyRequired: false, corsOk: true.
   Add `'bing-sidecar': 'Bing Image Creator via Bing Image Sidecar Orchestrator'` to IMAGE_API_LABEL.
4. src/features/settings/ConnectionDialog.tsx:
   For imageApi === 'bing-sidecar', hide base URL / API key / proxy fields and render a
   status block calling bingSidecarHello() (showing whether the extension is installed,
   enabled, whether a Bing Image Creator tab is open, and whether Bing is signed in or
   watermarked).
5. src/agent/prompts.ts:
   Add a short system prompt note when conn.imageApi === 'bing-sidecar' explaining:
   supported aspect ratios (1:1, 3:2, 2:3), max 4 images per request, model MAI-Image-2.6-Flash,
   reference-based edits (no masks), and that signed-out Bing tabs include a watermark.
6. Run `npm run typecheck` to verify.


4. SETUP FOR THE USER
---------------------
1. Install Bing Image Sidecar Orchestrator (Load unpacked: e:\NXTCloud\Tools\bing-images-orchestrator).
2. Open https://www.bing.com/images/create/ai-image-generator in a tab (sign in to Microsoft
   if you want watermark-free images).
3. Open the Bing Image Sidecar Orchestrator side panel and tick "Allow Alembic to control Bing".
4. In Alembic -> Settings -> Add provider -> Bing Image Creator (Bing Sidecar extension) -> Save.
